1. INTRODUCTION                                         *git-introduction*

git.nvim shows the state of the repository of the current file (or the
current directory) in up to five panels:

  Branches   always two rows: the upstream with its behind count, and HEAD
             with its ahead count and any merge/rebase in progress
  Tags       the tag at HEAD or the nearest tag, and unpushed tags; only
             shown when there is a tag
  Stashes    the most recent stash entries
  Files      conflicted, staged, unstaged and untracked files with +/- line
             counts; diffs can be expanded inline
  Graph      a lane-based graph of the most recent commits, including the
             upstream's when it is ahead; unpushed commits are marked `!`,
             incoming (not yet pulled) ones get a background color

Files can be staged, unstaged and discarded from the view, stashes popped,
applied and dropped, and commits and stashes opened. All git commands run
asynchronously; the view refreshes itself when the index or HEAD changes.
Unpushed and incoming (fetched, not yet pulled) commits are marked with `!`.
Unpushed commits on top of the upstream branch are drawn on a side lane to
the right that joins the upstream commit (`├─╯`); incoming commits on top of
your HEAD stay on the left lane and join your local history, which moves
one lane to the right (`╰─┤`). Once pushed / pulled, the graph is a straight
line again.

The view always fits its window and never scrolls as a whole. Files and Graph
split the height left after Branches, Tags and Stashes evenly and scroll on their
own: `j`/`k` past a box edge, `<C-e>` `<C-y>` `<C-d>` `<C-u>` `<C-f>` `<C-b>`
`<PageDown>` `<PageUp>` (the box under the cursor, else the graph) and the
mouse wheel (the box under the mouse). The bottom border shows the visible range when a box overflows.

While any inline diff is open, only the Files box is shown, using the whole
view. `<CR>` on a commit shows only the Graph (30%) and a Commit box with the
commit (`git show`, 70%) below it; `<CR>` on the same commit or `q`/`<Esc>`
closes it again.

2. REQUIREMENTS                                         *git-requirements*

- Neovim >= 0.10
- git >= 2.23 on PATH
- Optional: a Nerd Font for icons (set `icons = false` otherwise)

Run |:checkhealth| git to verify.

==============================================================================
3. SETUP                                                       *git-setup*

The plugin works without calling setup. Commands are defined at startup;
Lua modules are only loaded when the view is first opened, so lazy-loading
is not needed. With lazy.nvim: >lua

  {
    "<you>/git.nvim",
    cmd = "GitStatus",
    keys = { { "<leader>gs", "<cmd>GitStatus<cr>", desc = "Git status" } },
    opts = {},
  }
<
==============================================================================
4. COMMANDS                                                 *git-commands*

                                                              *:GitStatus*
:GitStatus [kind]       Open the status view, or focus it when it is already
                        open. [kind] is one of `float`, `split`, `vsplit`,
                        `tab` and defaults to `status.window.kind`.
:GitStatus toggle       Open or close the view.
:GitStatus close        Close the view.
:GitStatus refresh      Refresh the open view.

<Plug>(GitStatus)       Open the view.
<Plug>(GitStatusToggle) Toggle the view.

5. KEYMAPS                                                   *git-keymaps*

Buffer-local mappings in the status view (press `?` for this list):

  s         Stage the file, all files of a section (on its header), or the
            selected lines in Visual mode. On conflicted files: mark resolved.
  u         Unstage (same targets as `s`).
  X         Discard unstaged changes / delete untracked files. Asks first.
            Staged changes must be unstaged before they can be discarded.
  <Tab> =   Toggle the inline diff of a file (on a header: of all files).
  <CR>      Open the file (on a diff line: at that line) or the stash
            (`git stash show -p`). On a commit: toggle its details box. The
            cursor moves into the details; `k` on their first line goes to
            the top of the graph, `q` back to the commit. On several commits
            selected in Visual mode: show them combined (each header, then
            one diff from the oldest one's parent to the newest).
  P A D     Pop / apply / drop the stash under the cursor (drop asks first).
  c         Commit menu: a popup lists the next key, which picks
              c c   commit the staged changes: the files box turns into an
                    editable commit message box (filetype `gitcommit`)
              c a   amend the last commit with the staged changes (or only
                    its message), starting from its message; asks first
                    when the commit is pushed already
  r         On a commit in the graph: revert it (`git revert`, asks first;
            merge commits are reverted against their first parent).
  R         On an unpushed commit in the graph: change its message. The
            last commit is amended; for an older one it and the commits
            above it are recreated. Staged and unstaged changes stay as
            they are.
  f         Fetch (`git fetch`) the branch's remote; a spinner shows in the
            Branches box meanwhile, then incoming commits show in the graph.
  q <Esc>   Close the commit message editor or the commit details if open,
            else the view. <Esc> only closes floating views.
  ?         Show the keymaps of the box under the cursor (in the commit
            message editor: of the editor).

In the commit message editor:

  <C-s> :w  Commit / amend / reword (normal and insert mode). The message
            is used as typed, `#` lines included; only surrounding blank
            lines are dropped.
  q <Esc>   Cancel (normal mode). A new commit's message is kept as a
            draft and comes back on the next `c c`.

The view's buffer has 'filetype' `gitstatus`, so a |FileType| autocommand
can add further mappings.

6. CONFIGURATION                                               *git-config*

Options shared by all features are at the top level; each feature has its
own table (currently only `status`, the |:GitStatus| dashboard).

Defaults: >lua

  require("git").setup({
    icons = true,          -- Nerd Font icons; false = plain ASCII labels
    timeout = 15000,       -- ms, for local git commands
    status = {
      window = {
        kind = "float",    -- "float" | "split" | "vsplit" | "tab"
        width = 0.8,       -- float size: fraction of the editor (<= 1)
        height = 0.9,      -- or absolute columns/lines (> 1)
        border = "none",   -- a |nvim_open_win()| border; "none" drops the title
      },
      protected_branches = { "main", "master" }, -- marked in the HEAD line
      graph = { max_commits = 12 },
      stash = { max = 5 },
      diff = { max_lines = 500 },  -- per inline diff
      untracked_files = "normal",  -- "normal" | "all" | "no"
      tags = {
        -- Detect local tags at HEAD that are missing on the remote. This runs
        -- `git ls-remote` (network), at most every `cache_ttl` seconds.
        check_remote = false,
        timeout = 5000,
        cache_ttl = 60,
      },
      fetch_timeout = 60000, -- ms, for `git fetch` (network)
      auto_refresh = true, -- refresh on index/HEAD changes, writes, focus
      refresh_debounce = 150,
      hints = true,        -- show key and git command hints in the panels
      keymaps = {
        stage = "s",
        unstage = "u",
        discard = "X",
        toggle_diff = { "<Tab>", "=" },
        open = "<CR>",
        stash_pop = "P",
        stash_apply = "A",
        stash_drop = "D",
        commit = "c",          -- commit menu; the next key picks:
        commit_create = "c",   --   commit the staged changes
        commit_amend = "a",    --   amend the last commit
        revert = "r",
        reword = "R",          -- change an unpushed commit's message
        fetch = "f",
        close = { "q", "<Esc>" },
        help = "?",
        -- In the commit message editor:
        commit_submit = "<C-s>",         -- normal and insert mode
        commit_abort = { "q", "<Esc>" }, -- normal mode; keeps the draft
      },
    },
  })
<
Set a keymap to `false` to disable it. Lists (`protected_branches`, keymap
lists) replace the defaults instead of being merged. Invalid options are
reported and the previous configuration is kept.

Dashboard options given at the top level (the layout before `status` was
introduced) still work: they are moved into `status` with a warning.

7. HIGHLIGHTS                                              *git-highlights*

All groups copy a standard group, so they follow the colorscheme, but with
italic and background removed: the plugin shows no italic text, and text
never hides the row backgrounds below it. Groups you define yourself
with |nvim_set_hl()| are left alone.

  GitStatusBorder           box borders            grey (#808080)
  GitStatusFloatTitle       float window title     -> FloatTitle
  GitStatusBoxTitle         box titles             -> Title
  GitStatusDim              hints, zero counts     -> Comment
  GitStatusLabel            Remote:, HEAD: ...     -> Keyword
  GitStatusTagLabel         tag labels             -> Label
  GitStatusTag              tag at HEAD            -> Constant
  GitStatusTagNearest       nearest tag            -> Special
  GitStatusTagUnpushed      unpushed tag           -> DiagnosticWarn
  GitStatusUpstream         upstream branch        -> String
  GitStatusBranch           current branch         -> Type
  GitStatusProtected        protected marker       -> DiagnosticError
  GitStatusAhead            ahead count            -> DiagnosticInfo
  GitStatusBehind           behind count           -> DiagnosticWarn
  GitStatusWarning          operation in progress  -> WarningMsg
  GitStatusStash            stash entries          -> Special
  GitStatusSection{Conflicted,Staged,Unstaged,Untracked}   section headers
  GitStatus{Conflicted,Staged,Unstaged,Untracked}          file markers
  GitStatusFile             file names             -> Normal
  GitStatusAdded            +N                     -> Added
  GitStatusDeleted          -N                     -> Removed
  GitStatusGraph            graph lines            -> Comment
  GitStatusGraphCommit      commit node            -> Function
  GitStatusGraphMerge       merge node             -> Statement
  GitStatusGraphUnpushed    unpushed node and !    -> Added
  GitStatusGraphIncoming    incoming node and !    -> DiagnosticWarn
  GitStatusHash             pushed commit hash     -> Identifier
  GitStatusHashUnpushed     unpushed commit hash   -> Added
  GitStatusHashIncoming     incoming commit hash   -> DiagnosticWarn
  GitStatusIncomingLine     incoming commit row    amber background
  GitStatusDeco             ref names (line above) grey (#8a8a8a)
  GitStatusSubject          commit subject         -> Normal
  GitStatusDiff{Add,Delete,Hunk,Header,Context}    inline diff lines

==============================================================================
8. LUA API                                                       *git-api*

  require("git").setup({opts})    Configure, see |git-config|.
  require("git").open({opts})     Open/focus. {opts}: `kind`, `cwd`.
  require("git").toggle({opts})   Toggle.
  require("git").close()          Close.
  require("git").refresh()        Refresh the open view.
